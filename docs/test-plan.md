# Тест-план

## 1. Назначение

Документ описывает подход к автоматизированному тестированию портфолио-проекта: цели, объём, стратегию, окружение, тестовые данные, критерии входа/выхода, риски и отчётность.

Проект демонстрирует построение фреймворка и покрытие основных пользовательских сценариев, а не тестирование реального коммерческого продукта.

## 2. Объекты тестирования

| Объект | Тип | Стенд |
|---|---|---|
| SauceDemo | Web UI | `https://www.saucedemo.com` |
| JSONPlaceholder | REST API | `https://jsonplaceholder.typicode.com` |
| ApiDemos | Android app | локальный emulator/device |

## 3. Цели

- Проверить основные бизнес-сценарии SauceDemo.
- Покрыть позитивные и негативные сценарии checkout.
- Проверить авторизацию, каталог, карточку товара, корзину и оформление заказа.
- Продемонстрировать Page Object Model, переиспользуемые компоненты и стабильные локаторы.
- Обеспечить воспроизводимый запуск локально и в CI.
- Формировать Allure-отчёт с шагами, скриншотами и вложениями.

## 4. Объём

### Входит в текущее покрытие

- Авторизация: валидный пользователь, неверные данные, locked user, пустые поля, закрытие ошибки.
- Access control: защищённые страницы недоступны после logout.
- Каталог: 6 товаров, поля карточек, сортировка по имени и цене.
- Burger menu: открытие/закрытие, состав, logout, All Items, Reset App State.
- Карточка товара: открытие, имя, цена, описание, возврат, add/remove.
- Корзина: добавление, содержимое, количество, цена, удаление, возврат в каталог.
- Checkout: happy path с одним и несколькими товарами, пересчёт totals, обязательные поля, закрытие ошибки, отмена на двух шагах.
- Cross-browser smoke: Chrome и Firefox в CI.
- Параллельный запуск: 2 потока, отдельный WebDriver на поток.
- Точечный retry: 2 попытки для известных нестабильных UI-тестов.
- API: получение и создание поста.
- Mobile: запуск настроенного приложения.

### Не входит в текущее покрытие

- Реальная оплата и платёжные интеграции.
- Производительность и нагрузка.
- Безопасность.
- Accessibility.
- Полная cross-browser matrix: Safari/WebKit и Edge в CI.
- Responsive-тестирование.
- Полное покрытие мобильного приложения.
- Тестирование внешних переходов About и социальных ссылок.

## 5. Стратегия

Используется риск-ориентированный подход: приоритет отдаётся пользовательскому пути покупки.

### Уровни

1. **Функциональные UI-тесты** — проверка отдельных страниц и компонентов.
2. **Интеграционные UI-тесты** — взаимодействие каталога, карточки товара и корзины.
3. **E2E happy path** — полный путь от логина до подтверждения заказа.
4. **Негативные проверки** — ошибки валидации и отмена checkout.
5. **API smoke** — базовые CRUD-операции.
6. **Mobile smoke** — запуск приложения.

### Принципы

- Page Object Model.
- Приоритет `data-test` и стабильных локаторов.
- Ожидания через условия Selenide, без `Thread.sleep`.
- Один тест — одна проверяемая бизнес-ценность.
- Изоляция тестов: новый браузер и чистая сессия.
- Параллельные тесты не делят изменяемое состояние и файлы.
- Retry не маскирует дефекты: только явно помеченные тесты, максимум 2 попытки.
- Тестовые данные отделены от кода страниц.

## 7. Тестовые данные

### Пользователи

Файл:

```text
src/test/resources/testdata/users.json
```

| Ключ | Назначение |
|---|---|
| `standard` | Позитивные сценарии |
| `locked` | Проверка заблокированного пользователя |

### Товары

Файл:

```text
src/test/resources/testdata/products.json
```

Содержит:

- `products` — товары по ключам (`backpack`, `bikeLight`, `boltTShirt` и т.д.) с именем и ценой;
- `catalog.count` — количество товаров;
- `catalog.nameAsc`, `catalog.nameDesc`, `catalog.priceAsc`, `catalog.priceDesc` — ожидаемый порядок для сортировок.

### Checkout

Файл:

```text
src/test/resources/testdata/checkout.json
```

Содержит покупателя, платёжные данные, способ доставки и ожидаемые суммы для заказов `singleProduct` и `multipleProducts`. Тесты читают значения через `TestData`, без дублирования в Java-коде.

### API

JSONPlaceholder, тестовый пост создаётся с заголовком `QA automation portfolio`.

- Критичные и блокирующие дефекты отсутствуют.
- Результаты доступны в Allure.
- CI-пайплайн завершился успешно.
- Cross-browser smoke прошёл в Chrome и Firefox.
- Для падений сохранены скриншоты и page source.

## 13. Риски

| Риск | Влияние | Митигация |
|---|---|---|
| Нестабильность демо-сайта | Ложные падения | Повторный запуск, стабильные `data-test` |
| Изменение DOM SauceDemo | Падения локаторов | Централизация локаторов в Page Objects |
| Фиксированные цены и налог | Ложные падения при изменении данных | Пересмотр ожидаемых значений |
| `Reset App State` не обновляет кнопку товара | Нестабильная проверка UI | Проверка после повторного входа в каталог |
| Анимация burger menu | Единичные флейки | Наблюдение, при необходимости — ожидание `aria-hidden` |
| Браузерные различия | Падения только в Firefox/другом движке | Smoke matrix Chrome/Firefox в CI |
| Параллельные браузеры | Нехватка CPU/памяти, рост флейков | `parallelism=2`, отдельный WebDriver на поток, наблюдение за временем и стабильностью |
| Retry скрывает дефекты | Ложноположительный результат | Только явная аннотация, 2 попытки, анализ флейков |
| Сетевые ограничения CI | Падения API/UI | Повторный запуск, диагностика artifacts |
| Отсутствие мобильного окружения | Mobile не проверяется в CI | Локальный запуск, отдельный pipeline в будущем |

## 14. Управление дефектами

Дефект фиксируется, если:

- тест падает стабильно;
- поведение воспроизводится вручную;
- ожидаемый результат подтверждён требованиями или фактическим поведением продукта.

Для падений в Allure сохраняются скриншот и page source. Флейки отделяются от реальных дефектов повторным запуском. Retry не считается подтверждением исправления: тест с `@RetryOnFailure` остаётся в списке на анализ.
